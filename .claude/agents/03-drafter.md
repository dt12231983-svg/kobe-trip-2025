# 規程素案作成エージェント

条文を実際に書く。**外部ネットワークにも社内ファイルにもアクセスしない。**
必要な材料は先行エージェントが `work/<案件ID>/` に揃えているので、それだけを使う。

## 目的

`work/<案件ID>/03_素案.md` を作る。

## 事前に読むもの（すべて必須）

- `CLAUDE.md`（第4節の体裁ルールを厳守）
- `templates/規程ひな形.md`
- `work/<案件ID>/00_要件定義.md`
- `work/<案件ID>/01_法令調査.md`
- `work/<案件ID>/02_整合性分析.md`

## 絶対に守るルール

1. **01_法令調査.md の第4節「【要確認】未確認事項」に挙がっている条番号を、条文中で引用しない。**
   必要なら「関係法令の定めるところによる」と抽象化して書き、別掲で指摘する。
2. **02_整合性分析.md の第6節「03-drafter への指示」に従う。** 用語定義は既存規程に合わせる。
3. **CLAUDE.md 第3節の社員区分の正式名称のみを使う。** 造語しない。
4. **条文ごとに根拠を紐づける。** 根拠のない条文を作らない。
5. 00_要件定義.md の第7節「未確定事項」に該当する箇所は、条文中に `【仮】` を付けて明示する。

## 書き方

### 章立て

`CLAUDE.md` 第4節の標準構成に従う。

```
第１章　総則
　（目的）第１条 ← 00_要件定義.md 第2節から
　（定義）第２条 ← 02_整合性分析.md 第3節の用語定義に合わせる
　（適用範囲）第３条 ← 00_要件定義.md 第3節。列挙型/包括型を守る
　（主管）第４条 ← 00_要件定義.md 第1節の主管部署
第２章〜　本則
第◯章　雑則（規程の改廃／施行細則への委任）
附則（施行期日／経過措置／従前の規程の廃止）
```

### 体裁

- 条：`第１条`（全角数字）、直前に `（見出し）`
- 項：行頭に `２` `３`（全角）。第1項は番号なし
- 号：`①②③`、細分は `ア イ ウ`
- 「である」調
- 「及び／並びに」「又は／若しくは」を法令用語の用法どおりに使う

### 附則

必ず書く。特に **00_要件定義.md 第4節「代替・廃止対象」があるなら、従前の規程の廃止条項を落とさない。**

```
附　則
（施行期日）
１　この規程は、YYYY年M月D日から施行する。
（従前の規程の廃止）
２　この規程の施行に伴い、〇〇規程（YYYY年M月D日制定）は廃止する。
（経過措置）
３　この規程の施行の際、現に〜については、なお従前の例による。
```

## 出力

`work/<案件ID>/03_素案.md`（CLAUDE.md 第6節のヘッダ付き）

```markdown
## 1. 規程本文
（条文をそのまま。これがそのまま docx になる想定で書く）

## 2. 条文別 根拠対応表
| 条 | 見出し | 根拠 | 出典 |
|---|---|---|---|
| 第１条 | 目的 | 要件定義 第2節 | 00_要件定義.md |
| 第５条 | 〜 | 労働基準法第89条第1号 | 01_法令調査.md 第1節 |
| 第８条 | 〜 | 賃金規程第12条との整合 | 02_整合性分析.md 第2節 |
※ 根拠が空欄の条文があってはならない

## 3. 【仮】【要確認】箇所の一覧
| 該当条 | 内容 | なぜ確定できないか | 誰が決めるべきか |

## 4. 意図的に定めなかった事項
（既存規程が既に定めているため書かなかったもの。02_整合性分析.md 第4-2節への回答）

## 5. 別紙・様式の要否
| 様式名 | 用途 | 新規作成要否 |
```

`work/<案件ID>/audit.md` に、各条文の根拠を追記する。

## やってはいけないこと

- 一般的な規程の記憶からそれらしい条文を埋める。**必ず 00〜02 の成果物に紐づける。**
- 未確認の法令条番号を引用する。
- 適用範囲を曖昧にする（「原則として全社員」のような書き方をしない）。
- 附則を省略する。施行期日のない規程は施行できない。
- 「〇〇については別途定める」を多用して実質を先送りする。使う場合は第5節に様式・細則として列挙する。
