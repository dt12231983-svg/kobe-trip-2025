# 現行規程 台帳更新

対象：$ARGUMENTS（未指定なら全規程）

`CLAUDE.md` を読んでから開始すること。

## 手順

### 1. `08-registry` を実行

引数が指定されていればその規程のみ、なければ全規程を対象に棚卸しさせる。

### 2. 結果を確認する

完了後、`registry/棚卸し報告.md` を**あなた自身が読む**。

### 3. 【要確認】の解消をユーザーに求める

`registry/棚卸し報告.md` 第2節に「現行版が確定できない規程」が挙がっている場合、
`AskUserQuestion` で1件ずつ確定してもらう（多い場合は上位5件まで。残りは報告のみ）。

> 「〇〇規程」の現行版が確定できません。
> (a) 〇〇（2025.8.1） — 推定：旧版
> (b) 〇〇　20260401改訂 — 推定：現行
> (c) 両方有効（層が異なるため併存が正しい）
> (d) 実物を確認してから決める

確定した回答を `registry/regulations.yaml` に反映し、該当エントリに
`last_verified_by: human` と `verified_at: <日付>` を付ける。
**これにより次回の 08-registry 実行時に上書きされなくなる。**

### 4. 不整合の報告

`registry/棚卸し報告.md` 第3節の内容をユーザーに報告する。

- 命名規則から外れているファイル → リネームの提案
- 複数フォルダへの重複配置 → どちらを正本とするかの確認
- HD層とEVGM層の併存 → 意図的か確認（ハラスメント防止規程など、併存が正しい場合がある）
- 残留ファイル（`~$` 等）→ 削除の提案

**ファイルのリネーム・削除・移動は提案にとどめ、実行しない。**
OneDrive 上の既存ファイルへの破壊的操作は行わない。

### 5. コミット

`registry/regulations.yaml` と `registry/棚卸し報告.md` をコミットする。

## 定期実行

この棚卸しは**四半期に1回**、または規程改定の前に実行することを推奨する。
`/loop` や Routine で定期化する場合は、第3節の対話部分をスキップし、
【要確認】の一覧を報告するだけの運用にする。

## 守ること

- OneDrive 上のファイルを削除・リネーム・移動しない。**読み取りと提案のみ。**
- `last_verified_by: human` が付いたエントリを上書きしない。
- 版が判別できないものを推測で `current` にしない。
